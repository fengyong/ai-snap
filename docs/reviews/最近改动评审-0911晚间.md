## 三、未落实 / 新发现问题

### P1（旧账重申）· SCK 运行时自检 V1–V7 仍未执行
上轮评审的合并前置条件。本轮 13 个提交无一涉及；`CaptureProviderSCK` 里只有注释提到"自检工具也会用到"，但自检入口不存在。**V4（`captureImage(in:)` 无 config 参数、吃默认 SCStreamConfiguration，Retina 输出存疑）依然是全项目最大的未验证风险**——现在热键让截图触达频率变高（任何应用前台 ⇧⌘A），一旦主路径输出非 Retina，所有截图都会糊。建议在下一批改动前先补这个 10 分钟的自检菜单项。

### P2（新发现）· 默认热键 ⇧⌘W 会全局遮蔽常用应用快捷键
Carbon 全局热键是会话级独占的：注册后 ⇧⌘W 不再到达任何前台应用。⇧⌘W 在主流浏览器里是"关闭窗口"（⌘W 只关标签页）级别的高频快捷键，开箱即被静默劫持，用户几乎不可能联想到是截图工具干的——和提交里自己抓出来的"⇧A 吞打字"是同一类隐蔽症状。⇧⌘A 相对安全（少见）。建议窗口截图默认换成更冷的组合（如 ⌥⌘W / ⇧⌘S→否，保存为；可考虑 ⌃⌘W 或 F2 类），或至少首次启动检测到冲突时提示。

### P3 · 三处小瑕疵
1. `HotkeyManager.register()` 的文档注释说"同一个 config 只会生效一次（后注册的会先撤掉旧的）"——**实现里没有去重/撤旧逻辑**。用户把两个动作设成同一组合时，第二个会报"已被其它应用占用"（实际是被自己的第一个注册占用，文案误导）。建议要么实现去重，要么改注释和文案。
2. `SettingsWindow.handleRecordedKey` 的注释（"只按修饰键时……继续等"）与行为不符：该分支会显示错误提示。实际上纯修饰键根本不产生 keyDown（是 flagsChanged），这个分支只会在真正不可用的完整组合（⇧A 等）触发——**行为是对的，注释是错的**。
3. `HotkeyManager.installHandlerIfNeeded()` 开括号后 `guard` 挤在同一行，格式瑕疵。

### P3（旧账）· 调试面板仍默认占据标注窗口右侧 1/3
Phase 0 清单项。性能优化后它不再拖慢拖拽，但普通用户视角它仍是个莫名的分屏。建议下批顺手处理（默认隐藏 + Cmd+D 开关）。
