## 一、确认的 Bug

### 1.【中】记住的画笔颜色，每次打开标注窗口都被强制重置成调色板第一个

调用顺序：

1. `AnnotationView` 初始化时按偏好恢复 `currentColor = prefs.color`（[AnnotationView.swift L170](../../Sources/AnnotationView.swift)）；
2. 随后 `AnnotationWindow` 创建工具栏，无条件调用 `rebuildColorButtons()`；
3. 该方法把颜色**强行覆盖为 `palette.colors.first`**，并永远给第一个按钮画选中边框（[AnnotationWindow.swift L671-L674](../../Sources/AnnotationWindow.swift)）。

**后果**：用户选了蓝色并重启（`didSet` 会把蓝色落盘），下次截图时先恢复成蓝、随即又被改成红色，且通过 `didSet` 把存好的蓝色覆盖掉。README 宣称的「偏好自动记住颜色、跨重启保留」实际失效；即使记住的颜色恰好在调色板里，高亮框也错误地落在第一个按钮上。

**建议**：重建按钮后，仅当调色板包含 `currentColor` 时高亮对应按钮、不写回颜色；只有切换调色板（cyclePalette）且当前色不在新板中时才回退到第一个。

### 2.【中】首次标注后应用永久获得 Dock 图标，违背「常驻状态栏、不占 Dock」定位

启动时 [AppDelegate.swift L11](../../Sources/AppDelegate.swift) 设为 `.accessory`；但每次打开标注窗口，[AnnotationWindow.swift L358](../../Sources/AnnotationWindow.swift) 都执行 `NSApp.setActivationPolicy(.regular)`，全工程再没有任何地方改回 `.accessory`（已 grep 确认仅这两处）。窗口关闭后策略不恢复，Dock 图标与 ⌘Tab 条目一直留到退出。设置窗口文案（「AISnap 常驻状态栏、不占 Dock」）也随之失真。

**建议**：窗口关闭（且无其他标注窗口）时恢复 `.accessory`；或评估标注窗口是否真的需要 `.regular`（accessory 应用同样可以成为 key window、挂菜单）。

### 3.【低~中】区域选择成功路径 NSCursor 栈失衡：一次 push 对应两次 pop

- push：[RegionSelectionWindow.swift L117](../../Sources/RegionSelectionWindow.swift)（`beginSelection`）
- 选区完成时 `stopInteracting()` 已 pop：[L159](../../Sources/RegionSelectionWindow.swift)
- 标注窗口关闭后 `hideOverlays()` 又 pop 一次：[L168](../../Sources/RegionSelectionWindow.swift)

取消路径（`cancelSelection → hideOverlays`）是平衡的；**成功路径是 1 push / 2 pop**。另外 AppDelegate 在新截图开始时对残留窗口调 `hideOverlays()` 也会再 pop。`push/pop` 不平衡违反 AppKit 契约，可能把系统或其他组件压入的光标弹出，造成光标显示异常。

**建议**：用一个 `cursorPushed` 布尔守卫，两个出口各只 pop 一次。

### 4.【低~中】贴图窗口同时开启两套拖动机制，与代码自己的注释矛盾

[PinWindow.swift L30](../../Sources/Pin/PinWindow.swift) 设了 `isMovableByWindowBackground = true`，而 [L98-L113](../../Sources/Pin/PinWindow.swift) 的注释明确说「不用系统机制、改自己算 origin」，却没把该开关关掉；`PinContentView` 也没有重写 `mouseDownCanMoveWindow`。

两套机制并存的结果取决于 AppKit 事件分发：要么系统拖窗循环吞掉 `mouseDragged`（手动代码成为死代码、注释所说的双击干扰仍在），要么窗口被移动两次（跟手 2× 位移）。二者都不是预期行为，**具体表现需真机拖动确认**，但配置矛盾本身是确定的。

**建议**：直接置 `isMovableByWindowBackground = false`（或重写 `mouseDownCanMoveWindow` 返回 false）。

### 5.【低】拖动附着箭头后撤销，只退回位置、不恢复附着关系

拖动中清空附着：[AnnotationView.swift L355-L359](../../Sources/AnnotationView.swift)；而 `.move` 的 undo/redo 只做反向平移（[AnnotationView+UndoRedo.swift L38-L44](../../Sources/AnnotationView+UndoRedo.swift) 与 L105-L110），不保存也不恢复 `startAttachment/endAttachment`。

**后果**：⌘Z 后箭头视觉上回到原端点，但逻辑上已脱离，之后再移动父对象，这根箭头不会跟随。

**建议**：把附着快照并入 `.move`（或把「拉断附着」单列一步 undo）。

### 6.【低】拖拽/旋转/缩放途中按 Esc，本次变换不进撤销栈且不可逆

[AnnotationView.swift L544-L546](../../Sources/AnnotationView.swift) 的 Esc 无条件 `state = .idle`。若此时正处于 `.moving/.rotating/.scaling`，随后的 `mouseUp`（L441-L462）落到 `.idle` 分支，不产生任何 undo 记录，`dragStartCenter` 也残留。对象停在被改变的位置（箭头还会被永久拉断附着），用户无法用 ⌘Z 还原。

**建议**：Esc 在变换中途时要么整体还原本次变换，要么按正常收尾记入撤销栈。

### 7.【低】历史窗口「复制」把像素尺寸当成点尺寸

[HistoryWindow.swift L222-L223](../../Sources/History/HistoryWindow.swift) 用 `image.width/height`（像素）构造 `NSImage` 逻辑尺寸。Retina 截图粘贴到按点解释尺寸的 App 时会放大 2 倍；主标注窗口的复制路径则是正确的点尺寸。同文件 L130 的缩略图也是同样写法（影响较小，可一并处理）。

**建议**：用 `entry.pixelScale` 还原逻辑尺寸（L211 已取到该值）。

### 8.【低】OCR 阅读顺序比较器不满足严格弱序

[TextRecognizer.swift L47-L55](../../Sources/OCR/TextRecognizer.swift)：「半行高容差算同一行」不是等价关系（不可传递）。三个框可构成 A≈B、B≈C、但 A 与 C 不同行且 x 序相反的循环，排序结果未定义（不崩溃，但个别版面阅读顺序会错）。

**建议**：先按行聚类（分带 / 并查集），行内再按 x 排序。

### 9.【很低】预发布版本号比较不符合其注释声称的 SemVer

[UpdateChecker.swift L47-L49](../../Sources/Update/UpdateChecker.swift)：数字部分相同且双方都是预发布时一律判等——`1.0.0-alpha` 与 `1.0.0-beta` 被判为同一版本，beta 通道不会提示更新。探针只覆盖了「预发布 < 正式版」。另 `1a` 被静默解析为 1，也值得收紧。若未来不发预发布可忽略。

**建议**：需要时按 SemVer 逐段比较预发布后缀（数字段按数值、字母段按 ASCII、数字段 < 字母段）。

### 10.【低，竞态】主屏在 init 与 freeze 两个时刻分别取 `NSScreen.main`

[RegionSelectionWindow.swift L35/L60](../../Sources/RegionSelectionWindow.swift) 在 init 时记下 `mainScreenFrame` 和副屏数组；[L82/L89](../../Sources/RegionSelectionWindow.swift) 异步冻结时重新取 `NSScreen.main` 并按下标把副屏冻帧塞进窗口。`NSScreen.main` 的定义是「key window 所在屏」，两次调用之间若 key window 换屏（全局快捷键唤起、App 激活过程中），会出现主屏冻帧与缓存 frame 不匹配导致裁剪错位、副屏冻帧张冠李戴。

**建议**：在 init 时一次性快照主屏与屏幕数组并贯穿冻结/裁剪全程（与已修掉的「finishSelection 里重新取 NSScreen.main」同源思路）。
