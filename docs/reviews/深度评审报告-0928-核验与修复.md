### P2-14 为什么不成立

`CapturedImage.logicalSize` 两个方向都用**同一个** `pixelScale` 推导：

```swift
NSSize(width:  CGFloat(image.width)  / max(pixelScale, 0.01),
       height: CGFloat(image.height) / max(pixelScale, 0.01))
```

所以 `pixels.width/pointSize.width ≡ pixels.height/pointSize.height ≡ pixelScale`，
宽度比与高度比**恒等**，没有可达的失真路径。它属于"加固建议"而不是缺陷。

### 这一轮抓到的一个自己写错的地方

`P2-12` 第一版写的是 `max(缩放值, 下限)`，探针立刻抓到：**本来就已经比下限小**的形状
（例如手工拖出来的 2×2 矩形）会在一次缩放操作里被"抬"到 4 —— 用户什么都没做，对象却自己变大了。
改成 `scaledExtent`（只止损、不放大：结果低于下限时停在下限，但已经更小的原样保持），
并留了一条 `factor=1 不改变尺寸` 的断言守着。

### 又一个被探针挡下的：α 掩码降分辨率会破坏边界精度

`P2-10` 第一版按报告的建议做成**低分辨率掩码**（缩到 1/8）。写完 `master_parity` 的新断言
全绿，但**全套跑起来 `postfix_probe` 红了**：

```
❌ 中线左侧（不透明）仍命中  —— hit = nil
```

原因是 1/8 下一个格子会横跨「不透明 / 透明」的界线：那张 100pt 宽、左半不透明的图在 2x 下
是 200px，缩到 25 格后每格 8px，x=48pt 落在第 12 格（覆盖 96..104px）—— **跨了界线**，
于是被判成透明。（顺带确认了 CG 在这种大比例缩小时并不做盒式平均，否则不会这么干脆。）

改成**全分辨率、每像素 1 字节的 alpha-only 掩码**：语义与原实现逐像素一致（边界精度不受损），
内存仍是原来的 1/4，TIFF 往返照样省掉。省下的那点内存不值得拿边界精度换 ——
而「边界精度」这件事，探针里本来就有一条断言在守着。

### 顺带澄清一处报告没说准的归类

报告把重复的那四处列成 `Models.swift:869/1180/1623` + `RedactionShape.swift:219`。
行号是对的，但**行 1180 属于 `StampObject`（正方形），不是 `StepBadge`** ——
`StepBadge` 的 `nearestPerimeterPoint` 是**径向投影**（把点投到半径 r 的圆上），
与矩形周长完全不是一回事，不该被合并（我第一次改就误改了它，靠编译错误挡下）。
`CircleShape` 的椭圆近似同理，也是独立实现。最终转发到 `RectPerimeter` 的是
**矩形 / 印章 / 聚光灯 / 打码**这四种。

### 一条**没有**判别力的断言，已删掉重写

第 16 节原来写的是"吸附状态没变就不置脏"——但**离屏环境里 `needsDisplay` 不可观测**：
视图不在窗口里时设 `true` 读回是 `false`，在窗口里时设 `false` 又读回 `true`（都实测过）。
把修复退回去，那条断言**照样全绿**。

已改为锚在**可观测的吸附状态**（`activeSnapPoint` 的设上/清掉/再设上）—— 那才是我重写这段
代码时真正可能弄坏的东西。至于"确实少重绘了"这个性能收益本身，在离屏环境里没有可靠的
可观测量，**由代码审阅保证**，这里如实记下来而不是拿一条空转断言充数。

### 没有自动断言的部分（如实记录）

- **P0-1 的"先确认再截图"**：`confirmDiscardIfNeeded()` 在有未保存标注时会 `runModal()`，
  探针里调用会挂住，所以行为靠代码审阅 + 手动验证。它能被自动守住的部分（`close()` 触发
