### P2-14 为什么不成立

`CapturedImage.logicalSize` 两个方向都用**同一个** `pixelScale` 推导：

```swift
NSSize(width:  CGFloat(image.width)  / max(pixelScale, 0.01),
       height: CGFloat(image.height) / max(pixelScale, 0.01))
```

所以 `pixels.width/pointSize.width ≡ pixels.height/pointSize.height ≡ pixelScale`，
宽度比与高度比**恒等**，没有可达的失真路径。它属于"加固建议"而不是缺陷。

### 报告本身需要修正的两处

1. **P1-3 给的修法不完整**：只加 `guard !imageView.isHidden else { return }` 会让面板显示成
   **一片空白** —— 因为 `toggleDebugPanel()` 显示面板时**不调用** `refreshDebugView()`。
   必须 gate + 在 `willShow` 时补一次刷新。
2. **P0-1 的严重度判断比我们上一轮更准确**：上一轮我们发现 `orderOut` 这条路径时，把它
   归为"窗口还活着、只是看不见，先不动"—— 实际上**再截一次图 `openAnnotationWindow`
   就会把 `annotationWindow` 指向新窗、旧窗被释放**，内容是真的丢。报告是对的。

## 二、本轮修复（8 个文件）

| 问题 | 修法 |
|---|---|
| **P0-1** | `startRegionCapture` 改为与窗口截图**完全一致**：先 `confirmDiscardIfNeeded()`，确认后 `close()`（而不是 `orderOut`）。`close()` 会触发 `onClose` 收掉冻结覆盖层 —— 原来那句"被 orderOut 而非 close，onClose 没触发，这里补收一次"的补丁也随之不再需要 |
| **P1-2** | `discardAndClose()` 不再走 `performClose`，改为 `confirmDiscardIfNeeded()` + `close()`。`close()` 自己不调 `windowShouldClose`（实测 0 次），所以"确认逻辑只有一份"的初衷仍然成立 |
| **P1-3** | `refreshDebugView` 加 `!imageView.isHidden` 早退；`toggleDebugPanel` 在显示时补一次刷新（报告缺的那一半） |
| **P1-4** | 命中层改**脏标记 + 读前补绘**：移动/旋转/缩放的拖拽分支只记 `hitLayerDirty`，`pickColorKey` 前与调试面板渲染前调用 `flushHitLayerIfNeeded()`。**不是**"拖拽期间干脆不画"——那样一旦将来有人在中途读命中层就会静默拿到旧数据；现在"忘了重绘"在构造上不可能发生 |
| **P1-5** | 切走取色器时释放整幅 RGBA 副本。**注意不能写成 `lazy var` + 赋 nil**：`lazy` 只初始化一次，赋过 nil 就不再装载，取色器会**永久失效**（已实测复现）。改用「可空存储 + 按需装载」 |
| **P1-6** | 加 `captureGeneration` 代号：`presentRegionSelection` 的 Task 在 `await freezeScreens()` 之后先验代号，过期就自己 `hideOverlays()` 收干净、不强推上屏；失败分支也只在"仍是当前这次"时才清引用/报错。`startWindowCapture` 加 `windowCaptureInFlight` 防重入 |
| **P1-7** | snap：只在吸附点**真的变了**时置脏；`TextShape.contentSize` 加缓存（键 = 字号 + 文本，颜色/对齐不影响测量） |
| **P2-8** | 启动时清掉超过 24 小时的临时 PNG（留一天，剪贴板里的文件 URL 引用基本都产生于本次会话） |
| **P2-11** | `InstallEventHandler` 的 OSStatus 纳入判断，失败按 `RegistrationError.systemError` 抛出；`handlerInstalled` 改到**成功之后**才置位 |
| **P2-13** | 校验 `HTTPURLResponse.statusCode`，非 2xx 报「服务器返回 HTTP 404」，不再误报成「清单格式不对」 |
| **P2-14** | 顺手改成双轴各算一次（当前恒等，改法零代价，防的是将来 `logicalSize` 来源变化） |

### 一条**没有**判别力的断言，已删掉重写

第 16 节原来写的是"吸附状态没变就不置脏"——但**离屏环境里 `needsDisplay` 不可观测**：
视图不在窗口里时设 `true` 读回是 `false`，在窗口里时设 `false` 又读回 `true`（都实测过）。
把修复退回去，那条断言**照样全绿**。

已改为锚在**可观测的吸附状态**（`activeSnapPoint` 的设上/清掉/再设上）—— 那才是我重写这段
代码时真正可能弄坏的东西。至于"确实少重绘了"这个性能收益本身，在离屏环境里没有可靠的
可观测量，**由代码审阅保证**，这里如实记下来而不是拿一条空转断言充数。

### 没有自动断言的部分（如实记录）

- **P0-1 的"先确认再截图"**：`confirmDiscardIfNeeded()` 在有未保存标注时会 `runModal()`，
  探针里调用会挂住，所以行为靠代码审阅 + 手动验证。它能被自动守住的部分（`close()` 触发
  `onClose`、AppDelegate 借此清掉窗口引用）已有断言。
- **P1-6 的竞态**：需要精确控制"冻结未完成时再触发一次截图"，探针里没有可靠的时序钩子。
