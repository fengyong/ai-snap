## 二、问题清单

### P2 · 就地标注：选区贴屏幕底边时工具栏出屏
`AnnotationWindow.swift` 锚定定位为 `y = anchor.minY - toolbarHeight`，无下限保护。用户框选屏幕最底部一条（冻结帧覆盖全屏，选区可以到 y≈0）时，窗口底边为负，工具栏整个沉到屏幕外——鼠标用户无法触及保存/复制按钮（键盘 Enter 仍可用，但用户不知道）。修法：origin 对 `visibleFrame.minY` 做 clamp（工具栏可与 Dock 重叠但不可出屏），或底部空间不足时把工具栏翻到画布上方。

### P2 · 缩放换算的双轨制未闭环（V4 的正式确认）
裁剪侧（`ScreenGeometry.pixelRect`）按 `imageSize / screenFrame` 反推缩放，**显示侧（`AppDelegate.openAnnotationWindow`）仍用 `backingScaleFactor` 换算逻辑尺寸**。若 `captureImage(in:)` 返回非原生分辨率（上批评审的 V4 未验证项），裁出的图像素减半，逻辑尺寸跟着减半，锚定画布会缩成选区的一半——两条换算路径会给出矛盾结果。
有一个好消息：就地标注的"画布正好压在选区上"本身构成了 V4 的**活体验证**——若 V4 失败，这个对齐会肉眼可见地崩，而提交描述的视觉行为表明它目前是对齐的（即本机上 `captureImage(in:)` 返回原生 Retina）。但这是间接证据。建议正式闭环：把实际缩放（`frozenImage 尺寸 / 屏幕逻辑尺寸`）随回调传给标注窗口，或捕获处加一行断言/日志。这样 V1/V4 从"碰巧验证"变成"构造性保证"。

### P3 · 三处小瑕疵
1. `PinWindow.zoom(by:at:)` 的 `at pointInWindow` 参数完全没用上（注释说锚点在中心）——删参数或实现锚点缩放，别留死参数。
2. `PinWindow.saveToFile` 注释说"转成 sRGB 再编码"，代码没有做任何转换——注释与实现不符（实际影响小，源图都是截图）。
3. `zoom` 用 `scrollingDeltaY` 未区分自然滚动方向偏好——"滚轮向上=放大"对自然滚动用户手感相反。属打磨项。
